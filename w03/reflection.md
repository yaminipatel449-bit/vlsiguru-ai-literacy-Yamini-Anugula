# Week 03 Reflection

### 1. Most Useful AI Tool & Task
**NotebookLM** was the most useful tool this week for grounded learning. By uploading introductory machine learning documentation and engineering notes as sources, it allowed me to ask targeted technical questions and immediately verify the answers using exact source citations.

### 2. Best Prompt Modification
Adding explicit **constraints and output formatting** (e.g., asking for answers under 200 words, using analogies, or asking the tool to quiz me interactively) produced the biggest jump in response quality compared to open-ended questions.

### 3. Claim Verification Insight
Verifying claims using official documentation showed that while AI tools excel at summarizing high-level workflows, precise syntax or tool capabilities must always be cross-checked with primary documentation (like official GitHub repositories).

### 4. Key Learnings on Open-Source VLSI Tools
Explored OpenSTA and gained a practical understanding of how static timing analysis fits into the automated digital design flow. Understanding the role of SDC constraints and Liberty (`.lib`) files showed how abstract timing rules dictate physical implementation.

### 5. Questions for the ML Masterclass
1. How are ML surrogates (e.g., neural networks predicting timing slack) validated in production EDA environments where 100% precision is required for tapeout safety?
2. What are the best strategies for training ML models on specialized engineering data (like netlists or RTL) without risking data leakage or hallucinated outputs?
